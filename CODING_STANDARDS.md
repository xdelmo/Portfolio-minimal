# Coding standards

Lessons from past failures. Read before writing tests or motion code, and check every diff against them in review.

Every failure that reaches CI is closed in the same pull request with the fix of its cause **and** a guard that stops it coming back: a lint rule, a test, a check in a script or hook. Only when no automatic guard is possible, a line here. Already automatic: lint on commit (`pre-commit`), any server already on port 4300 stops the e2e (`reuseExistingServer: false` in `playwright.config.ts`), the e2e specs a branch changes run 5 more times in CI and at the end of `verify` (`scripts/e2e-changed.sh`), branch names (`scripts/branch-name.mjs`), `node_modules` and Playwright's browsers out of step with the branch (`.githooks/post-checkout` runs `npm ci` and `playwright install` when a checkout changes `package-lock.json`; `scripts/env-check.mjs` stops `verify` in its first second otherwise).

- A test about a time window (five taps within 2 s, an intro that lifts by a deadline) must not depend on how fast Playwright acts: `locator.click()` waits for stability, about 0.5 s each in WebKit on CI. Use `page.mouse.click` at a measured position (`verify` repeats the changed specs 5 times; for a timing fix, `npm run e2e:webkit -- <spec> --repeat-each=10` too).
- Anything bounded by a deadline in CSS must be bounded the same way when GSAP takes over: GSAP's lag smoothing slows its clock on a busy main thread (`effects/intro.ts` sets a timer on the fallback's deadline).
- A timing assertion counts from what the app's own bound counts from, plus the lag of WebKit's frames in CI: the intro test waits 6 s for a 3.6 s bound that starts at the first render, not at the end of `goto`.
- Before pushing a template change, `grep -rn` the e2e for the attributes and texts you changed and run those specs on Chromium: seconds, against half an hour of CI (adding `noopener` broke two tests that wanted `rel="me"` exactly). For a CSS property grep its camelCase too (`scroll-padding` and `scrollPaddingTop`): code and tests read it through `getComputedStyle`.
- The motion effects start one task at a time after the first paint, and their pins make the page taller: a test that scrolls or measures right after loading the home finds its target moved (issue #86, red CI on `devel` and `v2` after green pull requests). `e2e/fixtures.ts` therefore waits, after every `page.goto`, until no `[data-motion="pending"]` is left; never bypass it with a raw navigation, and opt out (`test.use({ motionReady: false })`) only in a test about that moment.
- "WebKit encountered an internal error" on a `page.goto` (issue #125) is WebKit's web process dying, seen once on the Mac under OrbStack and never in CI or on the Linux PC even with four workers: `e2e/fixtures.ts` retries that one error once and annotates the test `webkit-internal-error`. If those annotations become frequent, give the OrbStack VM more memory or run `e2e:webkit` with `--workers=1` on the Mac; never widen the retry to other errors.
- Judge each check by its own exit code: in `a && b` a failing `a` skips `b` without a word (twice on 2026-10-08 a failed lint hid unit tests and an e2e run against a stale build). Run lint, tests and build as separate commands while iterating.
- An effect with a desktop and a phone version sets, in each, every transform property the other one moves: a resize across 1024px reverts the inline styles but not GSAP's cached transform, so the phones' `x` stayed on the tool rings (issue #109, guarded by `e2e/stack-levels.spec.ts`). Clearing the cache on revert instead breaks the new version's tweens.
- Under smooth scroll (`smoothScroll: true`) click only what needs no scrolling (the fixed header's links) or scroll and wait for the content to rest first: Playwright scrolls a half-hidden target into view and clicks once it looks stable, while the content is still gliding, and on a busy machine the click lands where the target was (issue #159, a pre-push run). Read positions only once the page has settled (`settledTop` in `e2e/smooth-scroll.spec.ts`): a ScrollTrigger refresh nudges the content again after it first comes to rest, so a scroll aimed at an element is aimed again until its check holds (`toPass`, issue #222: an aim taken before a refresh left a picture 87 px off centre).
- Test that a canvas animation runs by counting its draws (`e2e/field-draws.ts`), not by comparing its pixels over a few seconds: WebKit in CI's image draws the home at about 4 frames a second, and the canvas sometimes did not change within 5 s (issue #53).
- SplitText puts an `aria-label` with the text on the element it splits (`aria: 'auto'`, the default): fine on a heading, not allowed on a `<span>` or `<div>` without a role, which Lighthouse fails as "[aria-*] attributes do not match their roles" while our axe runs passed (issue #354, the contact title's label). Split a heading, or pass `aria: 'none'` (the text stays readable) and assert in an e2e that no `aria-label` is left.
- A GSAP timeline is thenable: a callback that returns one trips `no-misused-promises`; give it a block body.
- `gh pr edit` fails on this repo (retired Projects classic fields): edit pull requests through `gh api`.
